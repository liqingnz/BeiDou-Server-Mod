# BeiDou-Server-ASM 参考价值评估

> 评估日期：2026-08-16　　评估对象：`E:\Programming\MapleStoryServer\2026\BeiDou-Server-ASM`
>
> **结论：ASM 只做素材参考，不作为迁移基础；LK 移植路线不变。**
> 本文记录评估过程与全部实测数据，避免日后重复分析（wz 侧的哈希比对耗时数分钟）。

## 1. ASM 是什么

一个**已部署的运行目录**（含 `BeiDou.jar`、捆绑 JDK、`logs/`），不是源码仓库，**无 git 历史**。
目录结构对应本仓库的 `gms-server/`：`scripts/`、`scripts-zh-CN/`、`wz/`、`wz-zh-CN/`。

**血缘：与 LichKingMod 无关。** LK 的新增内容（通用美容券 `5159000-5159005`、
1.5 倍经验/爆率卡 `5211900`/`5360900`）在 ASM 中**一个都没有**。
ASM 是一支独立的、被服主大量定制过的 BeiDou 分支。

### 2.2 语言分层：架构冲突（否决「以 ASM 为基础」的决定性理由）

| | 当前仓库 | ASM |
|---|---|---|
| `wz/` | **英文基础层**（`Henesys Hair Style Coupon (VIP)`） | **已是中文**（`射手村美发店高级会员卡`） |
| `wz-zh-CN/` | 中文覆盖层，137 文件 | 51 文件，缺 Mob.wz 那 87 个 |

CLAUDE.md 的 `gms.service.language`（en-US / zh-CN）双语机制依赖「英文基础 + 中文覆盖」。
ASM 把这一层塌掉了：以它为基础等于**放弃 en-US 模式**，且中英客户端共用 `Data/`
的补丁映射关系需要重新设计。这是前置的产品决策，不是技术细节。

### 2.3 脚本：ASM 有增量，但整体落后于上游

| | 仅 ASM 有 | 仅当前有 | 内容不同 | 完全相同 |
|---|---|---|---|---|
| `scripts/`（英文层） | 1 | 59 | 81 | 1,839 |
| `scripts-zh-CN/` | **283** | 60 | **627** | 1,362 |

627 个差异中，52 个是本仓库 LK 移植改动造成的；其余 575 个中：

- **58 个纯粹是 ASM 落后**——我们用 `===`、ASM 还是 `==`（上游做过代码现代化改造，ASM 未跟上）
- **517 个有真实差异**，抽样后为三类混合：
  - **服主运营调参写死在脚本里**：黑龙 PQ 最少 2 人（我们 6）、等级上限 200（我们 255）、
    解限后 80–200（我们 1–999）；月光 PQ 51–200；某 NPC 经验 300 倍（我们 50 倍）；训练中心解除等级限制
  - **ASM 有而我们缺的汉化**：如 `reactor/5511000.js` 的 BOSS 召唤播报我们仍是英文
  - **ASM 文案更旧**：`9270041` 我们写「ETC 库存/插槽」更准确；`2040026` 对话与括号风格更旧

> BeiDou 的设计是走 `GameConfig`（`use_enable_party_level_limit_lift` 等），
> ASM 把运营口味硬编码进脚本。照搬等于把别人一个服的运营决策焊进代码库。

ASM 独有的 283 个脚本按目录：npc 107、**BeiDouSpecial 66**（脚本中心扩展：
角色美化脸型库、手册导航等）、portal 51、quest 38、event 13、reactor 5、item 2、map 1。

## 3. 地图导入的依赖分析（2026-08-16 追加）

ASM 独有的 421 个 Map.wz 文件 = **328 张真地图** + 93 个 Obj/Tile/Back/WorldMap 渲染资源。

328 张新地图的依赖核查：

| 依赖 | 被引用 | 我们缺 | ASM 能补 | **三方（我们/ASM/LK）都没有** |
|---|---|---|---|---|
| 怪物 Mob | 183 种 | 82 | 82 | 0 |
| NPC | 209 个 | 113 | 112 | **1** |
| 反应堆 Reactor | 55 个 | 53 | 35 | **18** |
| 传送脚本 | 64 个 | 59 | 32 | **27** |
| 地图名（String.wz/Map.img） | 328 张 | 309 | 259 | **50** |

**只搬 Map.wz 会得到刷不出怪、反应堆缺失、传送门点了没反应的空壳图。**
可行的导入是五件套：`Map.wz` + `Mob.wz` 增量 + `Npc.wz` 增量 + `Reactor.wz` 增量
+ 32 个传送脚本 + 地图名。

永久缺口（LK 也没有，需另找来源或接受门是死的）：

- 18 个反应堆：`2112018`、`2119100-2119102`、`2401100`、`2401200`、`6109015`、
  `6741008-6741014`、`6742013`、`6746000`、`6749001`、`6829100`、`7422000` 等
- 27 个传送脚本：`EternalNight0-5`、`tomato_*` 系列（8 个）、`passStage1-4`、
  `EvilSpirit00`、`gh00`、`leaveFish`、`lionMask_enter`、`out_ani`、`removeitem`、
  `ropeEarth1`、`sb_out`、`sb_present`、`StartHarpMsg`

新地图按区域：7 亿段 97 张（中国区）、8 亿段 73、2 亿段 66、**5 亿段 52**、
0 亿段 19、6 亿段 15、3 亿段 6。

> **地图名的分层问题**：ASM 的地图名是中文，按本仓库架构应进 `wz-zh-CN/String.wz/Map.img.xml`，
> 英文基础层 `wz/` 需另找或留空。中国区地图（7 亿段）只有中文名可以接受
> （BeiDou 现有东方神舟脚本本就只在 zh-CN 层）；2 亿/5 亿段是国际服地图，
> 英文名缺失会让 en-US 模式的世界地图显示空白。

### 若日后重启地图导入的建议路线

**按区域分组、连依赖打包进，每组进完启服冒烟测试**，不要一次性 328 张。

建议第一组做 **5 亿段的 52 张**：同时解锁克雷塞尔的 4 个 deferred
（`event/KrexelBattle.js`、`portal/treeboss00.js`、`reactor/5411001.js`、`npc/9270045.js`），
与 LK 移植直接咬合，范围最小、最易验证，可把「依赖打包 → 校验 → 冒烟」流程跑通。

## 4. 采集清单（如果只取不冲突的部分）

按价值和风险排序，全部为纯增量、零覆盖：

1. **wz 的 39,356 个新增文件**——我们没有的它才补，零冲突。一次性解决附录 D 的 35/41，
   并为批次 8 的 Character.wz 备料
2. **283 个新脚本**中的 `BeiDouSpecial/` 66 个——纯增量、不与现有冲突
3. **517 个真实差异里「ASM 有的汉化」**——单独捞出，不连带运营调参

明确**不采**：共有 wz 文件的 ASM 版本（丢 cooltime、中文覆盖英文基础层）、
运营调参、ASM 落后于上游的文案与代码风格。
